# 《汉字拼拼乐》产品需求文档

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 产品名称 | 汉字拼拼乐 |
| 文档版本 | V1.0 |
| 产品形态 | Web 互动识字游戏 |
| 目标设备 | 电脑、平板、手机浏览器 |
| 目标用户 | 3-7 岁初识字儿童；陪同学习的家长或老师 |
| 当前技术 | Vite、TypeScript、PixiJS、HTML/CSS |

## 2. 产品概述

### 2.1 产品定位

《汉字拼拼乐》是一款面向低龄儿童的轻量互动识字游戏。儿童通过观察物品图片或图标，将汉字部件拼成目标汉字，并通过读音、词语和动画反馈加深记忆。

### 2.2 核心价值

- 将偏旁、部件和具体物品建立联系。
- 通过拖拽、点击和即时反馈提高参与感。
- 用分主题场景降低识字学习的抽象感。
- 让儿童在较短时间内完成一组明确、可重复的学习任务。

### 2.3 当前版本目标

- 提供四个可直接进入的识字主题关卡。
- 支持部件拖拽和点击放置两种拼字方式。
- 提供答对、答错、语音、分数和完成反馈。
- 支持儿童独立完成单次学习流程。

## 3. 用户与使用场景

### 3.1 儿童用户

儿童能够看懂图片、汉字、简单图标和颜色反馈，但阅读长文本和理解复杂规则的能力有限。操作应以大按钮、少文字、明显状态和即时反馈为主。

### 3.2 家长或老师

家长或老师希望孩子在 5-10 分钟内完成一组练习，并能看到孩子是否完成、哪些字容易出错，以及是否愿意再次练习。

### 3.3 典型场景

1. 儿童打开页面，在关卡地图中选择一个主题。
2. 儿童看到目标物品和汉字提示，将部件放入拼字格。
3. 系统判断答案，答对后播放读音、展示词语并奖励分数。
4. 儿童完成当前主题后返回地图，选择其他主题或重复练习。

## 6. 核心流程

### 6.1 进入关卡

1. 页面默认展示关卡地图。
2. 地图展示四个主题的图标、名称和简介。
3. 儿童点击任意主题进入关卡。
4. 系统随机抽取题目并随机排列部件。
5. 进入关卡后显示场景、题目和拼字区域。

### 6.2 拼字流程

1. 系统展示目标汉字、拼音、词语和对应物品。
2. 系统展示若干部件和数量相同的拼字格。
3. 儿童将部件拖到格子，或先点击部件再点击目标格。
4. 所有格子填满后自动检查答案。
5. 正确时进入成功反馈。
6. 错误时标记正确和错误位置，保留正确部件并清除错误部件。

### 6.3 成功反馈

- 播放成功音效。
- 播放目标词语的中文语音。
- 播放场景动画或粒子动画。
- 显示目标字、完整词语和拼音。
- 增加分数和连续答对奖励。
- 普通关卡提供“下一题”和“返回地图”。
- 教室、商店完成全部题目后展示主题完成弹层。

### 6.4 返回地图

- 顶部提供“关卡地图”按钮。
- 返回地图时取消当前动画和计时器。
- 已完成关卡在地图中显示完成状态。
- 当前版本所有关卡均可直接进入。

## 7. 关卡设计

### 7.1 汉字果园

定位：通过水果学习形声或部件组合。

题目示例：桃、梨、苹、芒、柠、橙、柿、葡、樱、蕉。

表现要求：

- 使用果树作为背景场景。
- 未完成的水果弱化显示，完成后点亮。
- 完成本关时播放果园庆祝动画。

### 7.2 四季菜园

定位：通过蔬菜生长强化“答对后成长”的正反馈。

题目示例：茄、椒、菇、番、萝、苗、蒜、菜。

表现要求：

- 使用菜地、土壤和栅栏作为场景元素。
- 初始显示幼苗，答对后显示成熟蔬菜。
- 支持多块菜地和轻微浮动动画。

### 7.3 学习教室

定位：通过学习用品进行一组连续识字练习。

题目示例：笔、课、灯、包、讲、信、篮、粉。

表现要求：

- 使用黑板作为主视觉。
- 题目以卡片形式排列。
- 卡片按顺序解锁，避免儿童一次面对全部任务。
- 完成后显示总分和完成提示。

### 7.4 快乐商店

定位：通过生活物品建立汉字和日常场景的联系。

题目示例：奶、冰、糕、饼、杯、帽、箱、袋、袜。

表现要求：

- 使用货架和购物车作为主视觉。
- 商品按顺序解锁。
- 答对后商品动画飞入购物车。
- 购物车展示已完成商品和当前完成数量。

## 9. 题库数据要求

每道题目至少包含以下字段：

```ts
interface Question {
  word: string;
  wordPinyin: string;
  fullWord: string;
  fullPinyin: string;
  parts: string[];
  layout: 'horizontal' | 'vertical';
  visualAsset: string;
  exampleSentence?: string;
  explanation?: string;
}
```

题库校验规则：

- `parts` 必须至少包含两个部件。
- 部件顺序必须与目标汉字的教学拆分一致。
- 拼音、词语和图片必须互相匹配。
- 目标词语适合 3-7 岁儿童理解。
- 同一关卡内避免连续出现过于相似的题目。

## 10. 页面与交互要求

### 10.1 视觉层级

- 目标汉字是答题页面最醒目的文字。
- 拼字格必须大于普通文本，并保持固定尺寸。
- 可操作部件必须有明显边框、阴影或颜色状态。
- 错误、正确、锁定、完成等状态需要同时使用颜色和文字或图标表达。

### 10.2 操作反馈

- 可拖拽部件在按下、拖动和放置时有状态变化。
- 目标格在可放置时高亮。
- 已使用部件不可重复放置。
- 答题检查期间暂时禁用相关操作，避免重复提交。
- 所有主要按钮支持键盘焦点。

### 10.3 响应式要求

- 最小支持宽度：320px。
- 手机端优先保证拼字格、部件和主要按钮可点击。
- 教室和商店的多列布局在窄屏时自动调整。
- 页面不得出现横向滚动。
- 动画和反馈不得遮挡题目或操作区域。

## 11. 无障碍与儿童友好要求

- 使用语义化按钮、标题和区域标签。
- 图片或图标提供合理的辅助文本，装饰性元素使用 `aria-hidden`。
- 不只依赖颜色表达正确和错误状态。
- 支持键盘完成选择和放置。
- 支持 `prefers-reduced-motion`，减少动画对敏感用户的影响。
- 语音功能不可用时，游戏仍然可以完整进行。
- 文字短句化，避免大段说明。

## 12. 非功能需求

### 12.1 性能

- 首屏可交互时间目标不超过 3 秒（普通网络环境）。
- 场景动画在常见移动设备上保持流畅。
- 避免在每次渲染时重复创建大量 Pixi 对象。
- 不使用音效时不创建或不持续运行音频资源。

### 12.2 稳定性

- 切换关卡时清理所有计时器、动画和语音。
- 快速重复点击不会重复结算分数。
- 返回地图后不能继续触发上一关的答题回调。
- 题目数据缺失时提供可识别的错误处理，而不是静默失败。

### 12.3 兼容性

- 支持最新版 Chrome、Safari、Edge。
- 重点验证 iOS Safari、Android Chrome 和桌面 Chrome。
- 浏览器不支持语音或 Web Audio 时不影响核心拼字流程。

## 13. 数据与状态

当前版本使用内存保存状态，包括当前关卡、题目、分数、连击和完成关卡。后续版本应使用 `localStorage` 保存以下数据：

```ts
interface SavedProgress {
  completedLevels: string[];
  masteredWords: string[];
  mistakeCounts: Record<string, number>;
  soundEnabled: boolean;
  updatedAt: string;
}
```

保存失败时应继续允许用户游戏，并在控制台记录非敏感错误信息。

## 14. 验收标准

### 14.1 核心流程

- 打开页面后可以看到关卡地图。
- 四个关卡均可进入并正常显示对应场景。
- 每道题均可通过点击部件和格子完成。
- 桌面端拖拽能够完成放置。
- 正确答案只结算一次分数。
- 错误答案会清除错误部件并允许继续答题。
- 完成关卡后能够返回地图。

### 14.2 反馈与状态

- 答对后显示正确反馈、词语和拼音。
- 声音开关能够同时控制音效和语音。
- 教室和商店能够按顺序解锁题目或商品。
- 商店完成商品后，商品能够显示在购物车中。
- 页面刷新不会造成 JavaScript 报错。

### 14.3 工程检查

- `npm run check` 通过。
- `npm run build` 通过。
- 手机宽度 320px、375px 和桌面宽度 1440px 下无明显布局溢出。
- `prefers-reduced-motion` 开启时，核心功能仍然可用。

## 16. 当前已知问题与优化重点

1. 刷新页面后学习进度、分数和完成状态会丢失。
2. HTML5 原生拖拽在移动端兼容性不足。
3. 普通关卡、教室和商店存在重复的拼字状态和判断逻辑。
4. 目前只能等待错误答案自动清理，缺少主动撤回和清空操作。
5. 题目中的 `fruit` 字段已被用于水果、蔬菜、学习用品和生活物品，命名需要泛化。
6. 部分场景主要由 DOM 展示，PixiJS 中对应的场景演员暂未实现。
7. 还需要补充移动端、键盘、语音和快速重复操作测试。
